# CLEAR — MPS 数据整合平台

CLEAR 把每周两份互相独立的 MPS 数据整合成一份可交付结果：

1. **Global 数据**：读取本周 MPS 导出的全部源文件（一个文件夹），组成 Global 数据集；
2. **Local 数据**：读取本地员工手工维护的 MPS 文件，组成 Local 数据集；
3. **整合**：两份都完成后，按「Global 优先、Local 补缺、整行重复折叠」计算合并结果，写入永久整合记录。

Global 与 Local **完全独立、没有先后顺序**；整合必须等两份都完成。程序不要求一次做完：
关掉再开、换一天继续都可以，已完成的导入和整合记录都保存在本地 SQLite 数据库里。

---

## 1. 三个步骤，三个明确的状态

| 步骤 | 何时算「完成」 | 产物 |
| --- | --- | --- |
| Global 导入 | 点工具栏的 **完成 Global 导入** | 一个带版本号的 **Global 数据集** |
| Local 导入 | 选完文件、格式检查通过即完成 | 一个带版本号的 **Local 数据集** |
| 整合 | 两份都完成后点 **整合** | 合并数据集 + 一条整合记录 |

**完成导入就进入历史数据。** 完成 Global 导入或导入 Local 后，该周立即出现在左下角历史数据，年份/周选择器与「查看」
会自动跟随到该周；整合前显示 Global / Local，整合成功后增加整合行。底部状态栏的「已整合」仍只统计已经整合的周。

**每次启动都是一个空工作台。** 数据工作台、已导入文件和状态条不会自动显示上次会话的数据；
已完成的导入和整合数据从左下角历史数据查看；未完成的草稿在启动时丢弃。已完成的 Global / Local 仍保存在本地数据库中，
只有当你为同一周导入新数据或整合适配时才会重新进入当前工作台。

**Global 导入是草稿。** 导入文件夹或添加文件只填充草稿，草稿期间：
- 表格里能看到刚导入的数据；
- 「整合」不可用；
- 关掉程序草稿会被丢弃（不做半成品恢复），已完成的导入不受影响。

点「完成 Global 导入」才把草稿定稿为 `v1`、`v2`…… 并参与整合。

**添加是「补进当前导入」。**
- 草稿期间点「添加」，文件追加进当前草稿；
- 已经完成导入后再点「添加」，程序先把当前版本**复制**成新草稿，再追加；
- 再次点「完成 Global 导入」得到 `vN+1`，旧版本如果被整合记录引用就保留，否则被替换。

**Local 没有「完成」按钮**：一次成功导入就是一份完整数据集；重复导入生成新版本。

### 过期

任何一份新的**已完成**导入，都会让该周已有的整合变成 **已过期**：

- 状态条和整合数据上会标出「已过期」；历史里只有整合那一行带标记，Global / Local 行显示各自最新的版本和创建时间；
- 整合记录仍指向旧版本（历史里只有整合行标「已过期」）；Global / Local 行显示最新导入版本、刷新创建时间；
- 点「整合」会用最新的 Global / Local 重新计算，过期标记消失。

### 丢弃

- **清空**（工具栏垃圾桶）：只丢弃**尚未完成**的 Global 草稿；
- **丢弃本周导入**（状态条上的链接）：丢弃本周**尚未整合**的 Global / Local 数据；
  已入库的整合记录、历史版本都不动。

## 2. 界面

| 区域 | 内容 |
| --- | --- |
| 工具栏 | Global 组：导入文件夹 / 添加源文件 / **完成 Global 导入** / 已导入文件（含清空草稿）；Local 组：导入本地 MPS；整合与产出：整合 / 导出；参数、关于、退出 |
| 工作区状态条 | 当前周、Global 草稿或完成版本、Local 版本与文件名、整合状态（含已过期）、丢弃本周导入 |
| 整合数据（上） | 显示当前选中数据集；标题栏明确标出 `Global 草稿` / `Global 数据 vN` / `Local 数据 vN` / `整合数据 vN`，过期时标「整合已过期」；可搜索、排序、分页；周数据带源文件颜色与备注 |
| 已导入文件 | 位于 Global 组内，只列当前 Global（或草稿）的文件、每个文件的行数、读取失败原因；左侧数据集列固定为 `Global`，右侧状态列为 `导入中`（草稿）/ `已导入`（已完成）/ `读取失败`，不带整合的过期信息；Local 是一次完成的单文件，文件信息显示在状态条 |
| 历史数据（下左） | 按年份/周查询所有**已完成导入**的周（未整合也显示）：未整合时两行 Global / Local，整合后增加整合行；可分别查看与导出；Global / Local 显示最新版本，过期时只有整合行标「已过期」，周级也提示 |
| 运行日志（下右） | 导入、完成、整合、导出、丢弃、报错 |
| 状态栏 | 当前周 Global / Local 行数、已整合周数与行数、参数、数据库位置 |

## 3. 使用流程

1. **导入 Global 文件夹**：选择本周 MPS 导出目录，等待日志显示成功文件数。
2. 核对「已导入文件」；缺少文件就点「添加 Global 源文件」补进来。
3. 需要时删掉同名旧文件重新添加——同名文件只保留一份，后加的覆盖旧数据。
4. 点 **完成 Global 导入**，得到 Global 数据集 `v1`。
5. **导入本地 MPS**：选择 `BW_CN_MPS … (Month End).xlsx`；格式不合格会拒绝并指出位置。
6. 两份完成后点 **整合**，汇总窗口列出合并 / Global / Local 三份行数。
7. 工具栏 **导出** 写三表工作簿（MPS / Local / Global，默认名 `BW_CN_MPS Week39 2026.xlsx`）。
8. 完成 Global 导入或导入 Local 后，该周立即出现在左下角历史数据；整合前显示 Global / Local，整合后增加整合行。历史数据里可单独查看和导出每一份数据。

**换周**：当前周的导入尚未整合时，程序会拒绝导入另一周。先整合，或点「丢弃本周导入」清掉本周未整合的数据。
当前周已经整合（且没有新导入）后，可以直接开始下一周；Global 与 Local 仍然可以任意先后。

**重做**：重新导入同一周的数据，完成后再整合一次即可；旧的整合版本在历史里仍可查，直到被新整合取代。

## 4. 数据与安全

### 4.1 本地数据库

数据库位置：macOS `build/bin/data/clear.db`（打包后位于 `CLEAR.app` 同级），Windows 在程序目录的 `data/clear.db`。
程序只读写这个文件；`wails build -clean` 会清空 `build/bin`，打包脚本已处理数据的暂存与归还。

结构版本 **v5**：

| 表 | 用途 |
| --- | --- |
| `dataset` | 一次完整导入或合并结果：周码、种类、版本、状态（draft / ready）、行数、文件数、导入时间 |
| `dataset_row` | 数据行：A–O、周值 JSON、样式、条件格式、批注 |
| `dataset_file` | 数据集包含的源文件记录 |
| `integration` | 每周一条：当前引用的 Global / Local / 合并数据集与整合时间 |

旧版本（v4 及以前）的 `archive`、按周数据表和暂存表会在首次启动时自动迁移到 `dataset` / `dataset_row` / `integration`；
迁移前自动生成 `clear.db.v4.bak`，旧表随后删除。未完成的历史暂存数据按「启动丢弃草稿」规则丢弃。

### 4.2 数据安全规则

- 导入失败的文件不会写入数据集；完成导入时如果仍有失败文件，会要求确认。
- 整合只写入新的合并数据集和整合记录，**不修改** Global / Local 数据集。
- 被整合记录引用的版本不会被清理；重新导入只新增版本。
- 「清空」只删草稿；「丢弃本周导入」只删本周未整合的数据；历史整合永远不动。
- 启动时自动丢弃草稿，不会出现「上次导入到一半」的半成品。

## 5. 参数

`参数设定` 里的项目立即保存并用于下一次操作：

| 参数 | 说明 |
| --- | --- |
| 读取列数 | 默认 20；决定读取源文件前多少列 |
| LOC 筛选 | 默认 `WH_CNB`；LOC 列不等于它的行会被过滤 |
| 每页行数 | 主表格每页行数 |
| 表头显示 | 两行（业务含义 + 字段名）或一行 |
| 导出模式 | 纯数据（`.xlsx`）/ 原文件格式（`.xlsm`，保留宏） |

## 6. 导出

### 6.1 三表文件

整合之后，工具栏「导出」写一个工作簿：

| 工作表 | 内容 |
| --- | --- |
| MPS | 合并结果（Global 优先 + Local 补缺） |
| Local | 本周 Local 数据集 |
| Global | 本周 Global 数据集 |

三张表使用同一套表头和周列，行数与各自数据集一致；字体、边框和批注会随数据写入三张表。
颜色按业务规则保留：第 1、2 行标题/日期行和第 3 行筛选行保留颜色；数据行只有 **O 列为 CalcOH 或 CalcOH2**
的行，从 **P 列起**保留颜色；其余单元格使用默认无填充色。条件格式的信号色以静态底色保留。
2.1.5 之前导入的 Local 数据集没有保存 Local 样式，重新导入一次 Local 后 Local / 合并页才会带出原 Local 的颜色和批注。

**整合已过期时仍允许导出**：导出的是上次整合结果，界面会明确提示；需要最新结果请先重新整合。

### 6.2 单份数据

历史数据窗口可以把某个数据集单独导出为单页报表（纯数据或原文件格式）。
如果该周只有 Local 数据、没有 Global 源模板，导出会自动按**纯数据**格式生成（没有原始样式可复制）。

导出成功后用**弹出对话框**列出文件路径、内容、行数和大小（过期时附提示），不再在数据工作台上方
增加一条导出提示栏；只有失败时才用状态提示。

## 7. 构建

需要 Go、Node.js、pnpm/npm 和 Wails v2。

```bash
# macOS（Apple Silicon）
./scripts/build-darwin.sh
# 产物：build/bin/CLEAR.app 与 dist/CLEAR-2.3.5-darwin-arm64.zip

# Windows（在 Windows 上）
./scripts/build-windows.sh
# 产物：dist/CLEAR-2.3.5-windows-amd64.zip
```

构建脚本会在 `wails build -clean` 前把 `build/bin/data` 与 `build/bin/config` 暂存到 `build/.clear-build-stash`，
构建后归还；不要直接运行 `wails build -clean`，否则会删掉本地数据。

开发：

```bash
wails dev
```

Go 测试：

```bash
GOCACHE=/tmp/clear-gocache go test ./...
```

前端测试：

```bash
cd frontend && npm test
```

完整验收（需要 `raw_data` 和本地 MPS 文件）：

```bash
go run ./tools/e2e -in raw_data -local "…/BW_CN_MPS Week39 2026 (Month End).xlsx" -out /tmp/clear-e2e
```

## 9. 常见问题

**导入完成但表格是空的？**
检查「已导入文件」窗口里的状态；失败文件会显示原因。表格当前选中的可能是另一个数据集（Global / Local / 整合），用状态条的按钮切换。

**为什么「整合」按钮是灰的？**
Global 还在草稿（先点「完成 Global 导入」），或 Local 还没导入；两份必须属于同一周。

**关掉程序后草稿还在吗？启动后为什么是空白的？**
草稿在启动时丢弃。已完成的 Global / Local 和整合记录都在，但工作台按新会话打开，
数据工作台 / 已导入文件 / 状态条不会自动回放上次的数据；需要查看旧数据请用左下角历史数据。

**导入下一周被拒绝？**
当前周还有未整合的导入。先整合，或点状态条的「丢弃本周导入」。

**「清空」会把已整合的数据删掉吗？**
不会。它只删未完成的 Global 草稿；已完成的导入与历史整合不受影响。

**旧的 `clear.db` 能直接用吗？**
可以。首次启动会自动迁移到 v5，并留下 `clear.db.v4.bak`。旧版未完成的暂存数据会被丢弃。

**导出的文件为什么没有最新数据？**
如果状态显示「已过期」，导出的是上次整合结果；重新点「整合」后再导出。
