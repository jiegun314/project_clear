# CLEAR

> **C**onsolidation & **L**oading of **E**nterprise **A**nalytics for **R**eplenishment

CLEAR 把 MPS 系统导出的 Excel 周报表合并成本地数据库，并按周导出成可以继续下发的工作簿。
一周的 MPS 数据通常分散在十几个部门/工厂导出的 `.xlsm` 里：表头结构相同、内容各不相同，
人工复制粘贴既慢，又会丢颜色、丢备注、丢条件格式。CLEAR 把这些工作自动化：

**读取文件夹中的全部源文件 → 按 LOC 过滤 → 按 A–O 索引列合并 → 存入 SQLite →
界面分页浏览 / 搜索 / 排序 → 每周一次「整合」入库 → 导出只含 MPS 一页的 Excel**
（纯数据 `.xlsx`，或保留源文件样式与宏的 `.xlsm`）。

技术栈：**Go + Wails v2 + Excelize**，前端 **React 19 + Ant Design 6 + Lucide**。

## 1. 功能概览

| 模块 | 作用 |
| --- | --- |
| 工具栏 | 导入文件夹、添加单个文件、整合入库、清空临时数据、导出、查看已导入文件、参数设定、关于、退出 |

## 2. 环境要求

| 依赖 | 版本 | 说明 |
| --- | --- | --- |
| macOS | 13 及以上，Apple Silicon（arm64） | 主要验收平台；发布包只出 arm64（通用二进制体积近乎翻倍，见 [3.3 打包](#33-打包)） |

## 3. 安装与运行

### 3.1 安装依赖

```bash
# 进入项目目录（仓库根目录，含 go.mod / wails.json）
cd project_clear

# 1) Wails CLI（确保 $(go env GOPATH)/bin 在 PATH 中）
go install github.com/wailsapp/wails/v2/cmd/wails@v2.16.0

# 2) 前端依赖
npm --prefix frontend install

# 3) Go 依赖
go mod download
```

国内网络下如果拉取缓慢，可以临时使用镜像：

```bash
export GOPROXY=https://goproxy.cn,https://proxy.golang.org,direct
npm config set registry https://registry.npmmirror.com
```

### 3.2 开发模式运行

```bash
wails dev
```

- 修改前端代码即时热更新；修改 Go 代码会自动重新编译并重启。
- `wails dev` 的二进制在临时目录里，此时数据目录按**当前工作目录**解析，
  所以开发环境用的就是仓库根目录下的 `data/`、`config/`（见 [第 7 节](#7-数据与参数位置)）。
- 如果只想调前端样式，可以 `npm --prefix frontend run dev` 单独起 Vite；
  此时页面里没有 Wails 后端，会直接显示「未检测到 CLEAR 后端」，属正常现象。

### 3.3 打包

```bash
# 最简打包（仅 Apple Silicon），产物：build/bin/CLEAR.app
wails build -platform darwin/arm64 -clean

# 推荐：多一步 Info.plist / 图标的校验，刷新 LaunchServices 缓存，
# 并打包成 dist/CLEAR-1.5.5-darwin-arm64.zip
./scripts/build-darwin.sh
```

发布包只出 **darwin/arm64**：通用二进制（arm64 + x86_64）会把 Go 二进制复制一份，
压缩包从 9.1 MB 涨到 18.8 MB，而本项目不再声明支持 Intel Mac。
确实需要 Intel 版时，单独构建即可：`wails build -platform darwin/amd64`。

其他常用参数：

| 命令 | 用途 |
| --- | --- |
| `wails build -skipbindings` | 没有改动 Go 的导出方法时跳过绑定生成，构建更快 |
| `wails build -clean` | 清理缓存后重新构建（建议交付前使用） |
| `wails doctor` | 检查本机 Wails 依赖是否齐全 |

打包完成后双击 `build/bin/CLEAR.app` 即可运行。数据写在 **CLEAR.app 所在目录**下，
不是 app 包内部，重新打包不会连带清掉数据。

### 3.4 首次启动

- 程序会自动生成 `config/clear.yaml`（默认参数）与 `data/clear.db`（空数据库）。
- 运行目录不可写时（例如放在 `/Applications`、或 app 被系统隔离），自动回退到 `~/.clear/`。
- 若新位置还没有数据库、而旧位置（app 包内或 `~/.clear`）有，会自动复制过来并在日志里写明来源，
  原目录保持不变。

## 4. 功能模块使用方法

### 4.1 工具栏

从左到右依次是：

| 按钮 | 说明 |
| --- | --- |
| **导入文件夹中的所有源文件** | 选择一个文件夹，读取里面所有 `.xlsm` / `.xlsx`。这是**覆盖式**操作：会重新开始一份整合清单，并清掉之前未整合的临时数据 |
| **添加单个源文件** | 选择一或多个文件，**追加**到当前整合清单（读取、表头校验、合并逻辑与导入完全相同）。同一个文件不会重复添加：若该文件已在清单里，先提示「覆盖原有数据」，确认后只替换这个文件的数据行，其他文件不受影响。清单为空时等同于单文件导入 |
| **整合** | 把整合清单里的全部数据写入永久周数据表（`data_<周码>`），并把临时数据交给历史数据模块。重复整合同一个周码会**覆盖**原有数据并把整合时间刷新为本次时间 |
| **清空** | 删除**已导入但尚未整合**的临时数据与导出模板副本，同时清空「已导入文件」列表。整合之后临时数据已经不存在，按钮仍可用——此时它只结束那份文件记录，不碰任何已整合入库的数据 |
| **导出** | 按参数设定的模式导出。有临时数据时导出临时数据，否则导出最新整合的一周 |
| **已导入文件** | 按钮右侧直接显示 `N 个文件 · M 行`，点击弹出文件清单（见 4.3） |
| **参数设定 / 关于 / 退出** | 固定在工具栏最右侧 |

按钮均为图标形式，鼠标悬停显示功能说明；处理中的按钮会统一禁用并显示「处理中…」。

### 4.2 整合数据表格（上方）

表格标题会写明当前数据来源：`整合数据（临时）` 或 `整合数据（周码 2639）`，
右侧显示 `共 N 行 · M 个周列`。

- **搜索**：匹配 A–O 索引列（P1..P5、物料、描述、目录等），输入即筛（250ms 防抖）。
- **排序**：点击任意列表头切换升序/降序，排序由数据库执行，全部数据参与，不只是当前页。
- **分页**：底部固定分页条，可选 50 / 100 / 200 / 500 / 1000 行每页；表格只有一条竖向滚动条，
  分页控件不会随数据滚走。
- **周数据列**：从 P 列开始，每列一个周码。数值按**四舍五入取整**并带**千分位逗号**，
  0 与空值显示为 `-`；单元格底色来自源文件该格的填充色，格上如果有批注，
  鼠标悬停显示作者与正文。
- **表头**：默认两行——上行周码（如 `2639`），下行周起始日期 `YYYY/MM/DD`；
  可在 `clear.yaml` 里把 `headerDisplay` 改成 `oneRow` 合并成一行。
- **来源可追溯**：索引列悬停显示该行来自哪个文件、源文件第几行。
- **刷新**：搜索框右侧的刷新图标重新读取当前页。

### 4.3 已导入文件

点工具栏的「已导入文件」按钮（旁边就是 `N 个文件 · M 行`）打开清单：

| 列 | 内容 |
| --- | --- |
| 序号 | 清单内的顺序号 |
| 文件名 | 源文件名，悬停显示完整路径 |
| 导入行数 | 该文件命中 LOC 筛选后保留的数据行数 |
| 状态 | 已导入 / 读取失败（失败时悬停显示原因） |

同一个文件只占一行；再次添加同一个文件会覆盖它原来的那行数据。

点「整合」之后列表**不会消失**：它保留为这一批的导入记录，方便核对这周到底整合了哪些文件、各多少行
（状态列仍显示「已导入」）。点「清空」后列表清空——只结束这份记录，已整合入库的数据不受影响；
下一次导入或添加会重新开始一份列表。

### 4.4 历史数据（下方左侧）

只查询**已经整合入库**的数据，未整合的临时数据不会出现在这里。

1. 先选「年份」，再选「周」（例如 2026 年第 39 周）。
2. 点「查看」，或直接点列表里的某一行，弹出该周的全量数据窗口。
3. 列表每行显示：周码、起始日期、第几周、行数 / 文件数、整合时间。
   同一个周码只有一行，重复整合只会刷新它的行数与整合时间。

弹窗内可以：搜索索引列、点表头排序、切换每页行数（200/500/1000/2000/5000）、
**导出纯数据 (.xlsx)**、**导出原文件格式 (.xlsm)**（见 [第 6 节](#6-导出说明)）。

### 4.5 运行日志（下方右侧）

- 每行格式：`时:分:秒 [级别] 来源 正文`；级别为 信息 / 成功 / 警告 / 错误，用颜色区分。
- 顶部可按级别筛选（全部 / 信息 / 成功 / 警告 / 错误）。
- 「新日志置顶」：停留在顶部时自动跟随最新日志，向上翻阅时自动停住。
- 橡皮擦图标清空**当前界面上的日志**；磁盘上的按日日志文件仍然保留，便于事后排查。

### 4.6 参数设定

点工具栏的齿轮按钮打开：

| 参数 | 范围 / 默认 | 说明 |
| --- | --- | --- |
| 读取列数（从 P 列开始） | 1–200，默认 20 | 源文件第 55/56 行读取多少个周列（20 = P..AI） |
| LOC 筛选值（L 列） | 默认 `WH_CNB` | 只保留该 LOC 的数据行 |
| 每页显示行数 | 10–5000，默认 200 | 主表格默认每页行数 |
| 导出方式 | 纯数据（默认）/ 原文件格式 | 工具栏「导出」与历史数据弹窗的默认模式 |

底部提供「恢复默认」「取消」「保存」。保存后立即生效并写回 `config/clear.yaml`。
`clear.yaml` 里还有两个只在配置文件里调整的参数：`headerDisplay`（两行/单行表头）、
`exportDir`（上次使用的目录，程序会自己更新）。

### 4.7 状态栏

底部状态栏从左到右：临时数据（周码 + 行数，无则显示「无」）、已整合（周数 + 行数）、
读取列数、LOC 筛选、每页行数、导出模式，最右侧的「本地数据库」悬停可看到数据库文件路径。
执行导入 / 整合 / 导出时，状态栏左侧还会显示当前阶段与进度。

### 4.8 上下区域高度

「整合数据」与「历史数据 / 运行日志」之间有一条分隔条：

- 上下拖动调整两栏高度，双击恢复默认；
- 点击分隔条后可用 ↑ / ↓ 微调；
- 调整范围是启动时下方区域高度的 80%–120%，上方数据表始终保留至少 200px；
- 拉伸窗口时下方区域高度保持不变，多出来的空间都给数据表格。

## 5. 典型工作流（每周一次）

1. **打开程序**，确认状态栏的 LOC 筛选、读取列数符合本周要求（不符合就到参数设定里改）。
2. **导入文件夹中的所有源文件**：选择本周 MPS 导出目录，等待日志出现「完成：成功 N 个文件」。
3. **核对清单**：点「已导入文件」，确认文件数与数据行数符合预期。
4. **补文件**：如果少了某个部门/工厂的文件，用「添加单个源文件」补进来；
   如果是同一个文件重新导出的版本，确认覆盖提示后替换即可。
5. **整合**：点「整合」，日志会写明周码、行数与是否覆盖原有数据；
   表格自动切到该周的已整合数据。
6. **抽查与导出**：在「历史数据」里选中该周点「查看」，抽查几行数据、颜色和备注，
   然后直接导出（或回到工具栏点「导出」）。
7. 需要重做时：整合前用「清空」丢弃临时数据重来；整合后重新导入同一周再整合一次即可覆盖。

## 6. 导出说明

两种方式都**只输出 MPS 一页**，都保留表头、全部数据、单元格颜色、条件格式与备注；
区别只在于是否沿用源文件自身的样式与宏。

| 方式 | 文件 | 内容 |
| --- | --- | --- |
| **纯数据**（默认，`clean`） | `.xlsx` | 新建工作簿：表头 + 全部合并数据；不含宏 |
| **原文件格式**（`template`） | `.xlsm` | 以首个源文件为模板改写：工作簿样式、页面设置与宏保留，其余工作表（Datadump / PSI / Summary 等）全部删除 |

导出文件的版式（两种方式一致）：

| 导出行 | 内容 | 源文件中的位置 |
| --- | --- | --- |
| 1 | A–O 索引表头 + P 起的周码（如 2639） | 第 55 行 |
| 2 | 各周的起始日期 | 第 56 行 |
| 3 | 样式分隔行（无数据） | 第 57 行 |
| 4 起 | 全部合并数据 | 第 58 行起 |

源文件第 1–54 行是报表的标题/装饰区（不属于数据），**导出时整体丢弃**，数据整体上移 54 行；
条件格式里的公式引用也会同步上移。

## 7. 数据与参数位置

程序把运行期状态放在**运行程序所在目录**下，双击即用、也便于备份：

| 目录 | 内容 |
| --- | --- |
| `<程序目录>/data/` | `clear.db`（SQLite）、导出模板副本 `templates/`、按日日志 `logs/` |
| `<程序目录>/config/` | `clear.yaml` |

- macOS 打包成 `CLEAR.app` 时，「程序目录」指 **CLEAR.app 所在的那一层**，
  不是包内的 `Contents/MacOS`——这样数据不会被藏在 app 包里，重新打包也不会连带清掉。
- 该目录不可写时（例如装在 `/Applications`、或 app 被系统隔离），自动回退到 `~/.clear/`。
- `go run` / `wails dev` 会把二进制放进临时目录，此时以**当前工作目录**为准，
  否则每次运行都会拿到一个空数据库。
- 首次启动若新位置还没有数据库，而旧位置有，会自动复制过来并写进日志；**原目录保持不动**。
- 备份：退出程序后整体复制 `data/` 即可（数据库、模板、日志都在里面）。

`config/clear.yaml` 的全部参数：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `configVersion` | 2 | 参数版本，程序用于把旧版本默认值带过来，请勿手工修改 |
| `readColumns` | 20 | 从 P 列开始读取的周列数 |
| `locFilter` | WH_CNB | L 列（LOC）筛选值 |
| `pageSize` | 200 | 主界面每页行数 |
| `headerDisplay` | twoRow | 表头双行/单行显示 |
| `exportMode` | clean | 纯数据（clean）/ 原文件格式（template） |
| `exportDir` | — | 上次导出目录 |

## 8. 测试与验收

```bash
# 后端：全部单测 + 静态检查
go vet ./...
go test ./...

# 前端：类型检查 + 单元测试
npm --prefix frontend run typecheck
npm --prefix frontend test

# 端到端验收：用 raw_data/mps_data 里的真实工作簿跑通
# 导入 → 暂存查询 → 整合 → 导出 → 保真度审计 → 重复整合校验
go run ./tools/e2e -in raw_data/mps_data -out /tmp/clear-e2e
go run ./tools/e2e -in raw_data/mps_data -out /tmp/clear-e2e -clean   # 纯数据模式
```

`tools/e2e` 的可用参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `-in` | `raw_data/mps_data` | 源文件目录 |
| `-out` | `/tmp/clear-e2e` | 临时数据目录（数据库、导出文件） |
| `-clean` | `false` | 用纯数据模式导出 |
| `-keep` | `false` | 保留上一次的临时目录 |

验收脚本会检查：工作表只剩 MPS 一页、表头前 54 行已移除、A–O 表头与周码完整、
样式分隔行保留、LOC 筛选行数正确、条件格式与配色表（`dxfId`）在合法范围内、
批注条数与源文件一致、周数据逐格与源文件交叉校验、宏是否存在，
以及「重复整合同一周码时归档只有一条、时间刷新、数据不累加」。

## 9. 目录结构

```
main.go / app.go          Wails 入口与前端绑定（导入/添加/整合/清空/导出/状态/日志）
dialog.go                 文件选择器：导入 / 添加 / 导出，三平台统一走 Wails 内置对话框
dialog_options.go         选择器的选项映射（标题、默认目录、*.xlsm;*.xlsx 过滤器，含单测）
internal/config           YAML 参数与默认文件自举
internal/logging          内存环形缓冲 + 按日落盘
internal/mps              读取、周码模型、条件格式、批注、导出
internal/store            SQLite：暂存表 + 按周永久表 + 归档
internal/service          导入/添加/整合/清空的编排
frontend/src              React 界面（工具栏 / 数据表 / 已导入文件 / 历史 / 日志 / 状态栏）
scripts/build-darwin.sh   macOS 打包脚本（校验 plist 与图标、刷新缓存、打 zip）
tools/e2e                 端到端验收与保真度审计
tools/bindcheck           Wails 绑定返回值的 JSON 序列化检查
raw_data/mps_data         验收用的真实源文件
```

## 10. 关键实现说明

**条件格式是数据颜色的真正来源。** 这些工作簿每一数据行都带有自己的
`conditionalFormatting` 规则（把本行与相邻行比较，如 `(ROUND(P180,0)<P181)`），
且同一 `sqref` 下最多有 4 个独立块。excelize 的 `GetConditionalFormats` 以 sqref
为键做赋值，会丢掉其中 3 个，因此本项目改为**直接解析 sheet XML**，
把行号转换成相对锚点的偏移量保存，导出时再重锚到新行号并回写 zip。
`internal/mps/cfxml.go` 有对应单测。

**条件格式的配色表按批次重新编号。** 每条 `cfRule` 的 `dxfId` 只在自己那个工作簿里有意义
——13 个源文件各有各的 `<dxfs>` 表，A 文件的 296 和 B 文件的 296 是两种颜色。合并后如果
照抄 id，轻则颜色对不上，重则 id 超出导出文件的配色表范围，**Excel 会直接判工作表损坏**
并要求修复。所以读取时把每个文件的 `<dxf>` 按内容 intern 成批次内统一的 id，导出时再
追加到目标配色表并把规则重新指向（已存在的配色复用原索引，模板自身的配色不会被搬动）。
`internal/mps/dxf.go`，含单测。

**样式按签名去重存储。** 1516 行 × 35 列约 5.3 万个单元格，实际只有几百种不同样式；
签名 JSON 去重后存入 `cell_style` 表，导出时在目标工作簿中重建或复用。

**添加是「合并进清单」而不是「另起一份」。** 导入文件夹会重建暂存批次；添加则在同一个批次
里追加文件，并按文件 id 归属数据行，因此再次添加同一个文件时只删除它自己的行再写入新的，
文件数不会增长、旧数据不会累加。`internal/store/staging.go` 的 `MergeStaging`，含单测。

**数据表格按源文件的列位显示周数据。** 周列的取值来自 P 列起（`FirstWeekCol + i`），
并顺带把两样东西一起送到界面：源单元格的**填充底色**（由 `style_ids` 里的样式签名
还原成 `#RRGGBB`）和该格上的**批注**（悬停显示作者与正文）。占用宽度全部写死，
表格用 `tableLayout="fixed"` + 显式像素总宽，表头与表体由同一套宽度渲染，
不会各算各的导致错位。

**批注（注释）随行迁移，而不是随单元格停留。** 源文件里所有批注都是 Office 365 的
线程批注，Excel 同时会在传统 `comments1.xml` 里留一段 `[线程批注] / 你的Excel版本…`
的占位文案。读取时先解析工作表 rels，再分别读 `xl/threadedComments/*.xml` 与
`xl/comments1.xml`，**以线程批注为准**（作者取自 `xl/persons/person.xml`），只有传统
批注的文件则从占位文案的 `注释:` 之后回收正文。批注随数据行一起经过
`stg_row.comments` → 周表的 `comments` 列 → 导出，并重新锚定到合并后的新行号。
excelize 只认传统批注，所以导出时会把数据区残留的线程批注从 zip 里剥掉，避免
旧锚点落到别的行上（`internal/mps/comments.go`，含单测）。

**导出优先使用模板改写。** 以首个成功读取的源文件副本为模板，覆盖式写入数据区，
保留宏（`vbaProject.bin` 字节一致）、数据透视、切片器等全部部件；
`ReplaceParts` 对未改动的 zip 条目使用 `CreateRaw` 原样复制。
若模板不可用则回退为干净重建，只输出 MPS 表并移植源文件的 `dxfs`。

**读取走流式 XML 而非 `excelize.GetRows`。** 后者对每个单元格都要做数字格式解析，
在这类 4–8 MB 工作簿上单文件约 13 秒；改为流式解析后约 1.8 秒，
13 个文件的导入从 2 分 58 秒降到 24 秒。

## 11. 已知限制

- **Wails v2 是单窗口框架**（`WindowCreate` 自 v3 起才提供）。需求中的
  “弹出单独窗口”因此实现为应用内的全屏遮罩层，功能与交互一致，但不是独立 OS 窗口。
- **文件选择器三平台共用一套实现**（`dialog.go`，Wails 内置的 `OpenDirectoryDialog` /
  `OpenFileDialog` / `OpenMultipleFilesDialog` / `SaveFileDialog`）。
  v1.5.3 起三平台共用同一实现；v1.5.2 及以前 macOS 单独用 Objective-C 调 `NSOpenPanel`，是因为 Wails v2 的绑定方法
  跑在 goroutine 里、面板以 sheet 形式贴在窗口上，早期出现过「面板闪现即关」；后来定位到
  真正原因是启动时 `WindowShow`/`WindowUnminimise` 抢走了窗口的 key 状态（已在 `b829dd8`
  移除），本版实测文件夹选择、多选文件（带过滤器）、保存面板三类对话框在 macOS 上开/关/重开
  均稳定，于是删掉了 shim，工程里不再有 Objective-C 与自带的 cgo 选择器代码。
  Windows 版已通过 `windows/amd64` 交叉编译与静态检查，但尚未在 Windows 真机上做验收。
- 表头不一致的文件按需求判为失败跳过，不会自动按周码对齐补列。
- **批注导出为传统批注。** 线程批注的正文、作者、回复都会保留，但 Excel 里显示的
  是经典便签而不是线程批注气泡；excelize 不支持写入线程批注。
- 导出的批注作者取自源文件记录；源文件没记作者时统一记为 `CLEAR`。
- **界面上的单元格底色取自静态填充色**，不还原条件格式算出来的颜色；条件格式规则
  仍会被完整读取并在导出时原样写回，只是界面不做公式求值。数值本身按正/负/零着色。
- 同一个文件的判定依据是**完整路径**：把同一个工作簿复制成另一个文件名/路径再添加，
  会被当成新文件（数据会叠加）。

## 12. 常见问题

**双击没反应，或页面显示「未检测到 CLEAR 后端」？**
界面必须通过打包后的 `CLEAR.app` 运行，直接在浏览器里打开 `frontend/dist/index.html`
没有后端绑定。开发时请用 `wails dev`。

**导入完成但表格是空的？**
按顺序检查：①「已导入文件」窗口里对应文件的状态是否为「读取失败」；
② 参数设定的 LOC 筛选值是否与源文件 L 列一致；③ 源文件第 55 行表头与首个文件是否完全一致
（不一致的文件会被判为失败并在日志中写明原因）。

**数据存在哪里？怎么备份或迁移？**
都在程序目录的 `data/` 下（`clear.db` + `templates/` + `logs/`）。退出程序后整体复制即可。
状态栏最右侧「本地数据库」悬停可看到实际路径。

**「清空」会把已整合的数据删掉吗？**
不会。清空只删除已导入但未整合的临时数据和它的导出模板；已整合的周数据、历史数据面板
都不受影响。整合之后按钮依然可用，那时它只清空「已导入文件」列表，不动任何已入库数据。
想更新已整合的一周，重新导入同一周的数据再整合一次即可覆盖。

**同一个文件不小心加了两次？**
不会产生重复数据：第二次添加会先提示「覆盖原有数据」，确认后只替换该文件的行，
清单里的其他文件不受影响。列表里同一个文件永远只有一行。

**导出的 Excel 打不开、提示修复？**
早期版本有 `dxfId` 越界与 `conditionalFormatting` 元素顺序问题，均已修复并通过
真实 Excel 打开验证。若仍遇到，请保留 `data/logs/` 里的日志、对应的源文件与导出文件
以便复现。

**每周做一次要重复哪些步骤？**
导入文件夹 → 核对「已导入文件」→（缺文件就添加）→ 整合 → 在历史数据里抽查 → 导出。
详见 [第 5 节](#5-典型工作流每周一次)。
